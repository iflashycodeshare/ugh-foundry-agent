# Embedded Enabler Protocols

> Operational guidance for each embedded enabler type deployed by the Program Executive.
> Required at Tier 3 when enablers are activated.
> Maintained by the **Program Executive**.

**Last Updated:** 2026-08-28

## Enabler Roster

| Enabler Type | Deployed By | Reports To | Primary Responsibility |
|-------------|-------------|------------|------------------------|
| Security | PX | PX + Ops Chief | Security posture, ATO readiness, SDL compliance |
| Acquisition (CO + COR) | PX | PX | Contract compliance, procurement oversight |
| Finance (CGFS) | PX | PX | Budget execution, cost allocation, FinOps governance |
| ERM & Governance | PX | PX | Enterprise risk management, policy compliance |
| OIG Readiness | PX | PX | Audit preparation, finding remediation, compliance mapping |

## Engagement Model

### Activation
- Enablers are activated by the Program Executive at Tier 3 initialization
- Each enabler operates cross-cutting across all projects and rings
- Enablers participate in governance forums per the forums protocol

### Review Cadence

| Enabler | Review Trigger | Mandatory Rings |
|---------|---------------|------------------|
| Security | Any security-relevant change | Ring 0 (threat model), Ring 3 (IV&V), Ring 5 (sign-off) |
| Acquisition | Contract milestones, scope changes | Ring 1 (planning), Ring 4 (release) |
| Finance | Budget threshold events, ring transitions | All ring gates |
| ERM & Governance | Risk register updates, policy changes | Ring 0 (intake), Ring 3 (IV&V) |
| OIG Readiness | Audit schedule events, finding updates | Ring 3 (IV&V), Ring 5 (pre-prod) |

### Escalation Authority
- Enablers may escalate CRITICAL findings directly to PX
- MAJOR findings are routed through the relevant governance forum
- Enablers cannot block ring gates unilaterally — PX makes final gate decisions
