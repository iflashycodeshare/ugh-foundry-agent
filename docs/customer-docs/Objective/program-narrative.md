# Program Narrative

## UHG Provider Network Intelligence Agent

Provider Network Operations analysts currently reconcile provider contracts, credentialing, location amendments, and provider-directory details across four systems. The contractual objective is an authenticated Microsoft Foundry hosted agent that answers natural-language provider-network questions with grounded, cited information, reducing the current 18-minute average handling time and improving consistency. It is a read-only service: it must not alter systems of record, handle member or patient clinical data, adjudicate claims, or provide coverage determinations.

The source of scope authority is the statement of work (SOW). It makes grounded answers, record-level citations, business-unit restriction, coverage-determination refusal, seven-year audit retention, uncertainty rather than guessing, US processing, tenant containment, Responsible AI assessment, and security/ATO release readiness contractual requirements. It also defines a median response-time objective below six seconds, 99.5 percent business-hours availability, and inline quality rating as a Could priority.

Stakeholder discovery adds operational detail without changing the SOW's authority. Analysts require answers to be explicitly tied to the relevant provider location because a group relationship cannot safely stand in for site-specific contract status. Authorization must be applied at query time before retrieval. A prohibited coverage request must be refused, routed to the benefits team, and retained as audit evidence. Discovery also emphasizes precise uncertainty when an amendment cannot be found, a freshness expectation for amendments loaded the prior day, and optional negative feedback with a comment. The feedback detail remains subordinate to the SOW's Could priority and is not promoted to a Must or first-release commitment.

Platform constraints independently confirm several discovery controls: Entra-only identity, managed identity access without static credentials, pre-retrieval business-unit authorization, US and UHG-tenant data boundaries, no training or fine tuning using customer data, diagnostic payload exclusion, approved UHG services, model allowlist and change governance, and fixed access modes for the four data sources. The amendment register is a nightly export. This conflicts with the stakeholder expectation that yesterday's amendments should be reflected: the sources do not establish whether an amendment loaded after the nightly export is acceptable. The business must agree the usable freshness expectation; the agent must not represent intra-day amendments as available.

Ring 0 has captured requirements and constraints only. It has not selected a target architecture, produced architecture models, completed a threat model, received the required security validation, completed the mandatory customer-document brainstorming process, or passed a gate.
